# Important README to Understand the Changes Sophie Made

This branch contains the faster, assignment-aligned organizational pattern
mining pipeline and the result artefacts that are useful for reporting.

The key idea is that the Petri net and BIG alignments should be discovered on
the original process activity labels, while the exported BIG instance graph
nodes still preserve the organizational labels such as
`activity_org:resource`. This keeps Inductive Miner and BIG tractable, while
SUBDUE still mines organizational activity-resource behavior.

## What Changed in the Code

### 1. Preprocessing

File: `preprocess.py`

- The log still relabels every event as `<activity>_<selected attribute>`.
- The original activity is preserved in `original_activity`.
- The code prints available event attributes and recommends lower-cardinality
  organizational attributes before using `org:resource`.
- Tiny placeholder XES files can resolve to the real dataset location.

### 2. Instance Graph Generation

Files: `instance_graphs.py`, `big_engine.py`

- Added the frequent trace variant filter before Inductive Miner.
- Default coverage is `0.80`, meaning the most frequent variants are retained
  until they cover 80% of the cases.
- Variants are computed on `original_activity` by default.
- The Petri net is discovered on `original_activity` instead of the
  resource-enriched labels.
- BIG alignment also uses `original_activity`.
- The generated instance graph nodes still use the relabelled organizational
  labels such as `W-Handle-leads-schedule_User_1`.
- BIG progress is printed during long runs.
- Run statistics are saved in `variant_filter_stats.json`.

This fixes the earlier problem where Inductive Miner/BIG were asked to work on
thousands of fused `activity_resource` labels, which made the full dataset
unusable.

### 3. SUBDUE Pattern Mining

File: `pattern_mining.py`

- `main.py` now passes the same SUBDUE parameters that `pattern_mining.py`
  expects, so the one-command run reproduces the intended mining setup.
- Added a mining filter before SUBDUE with `--exclude-activities`.
- Default low-value activities for reporting experiments:
  `start`, `end`, `A-Create-Application`, `A-Submitted`.
- The filter removes trivial bookkeeping prefixes before SUBDUE so that the
  strongest mined patterns are closer to behavioral work-practice patterns.
- SUBDUE hierarchy/compression is handled:
  compressed `PATTERN-i-j` nodes are kept in hierarchy files and expanded back
  to original events for stats, evaluation, and visualization.
- Outputs include:
  - `pattern_stats.csv`
  - `trace_pattern_matrix.csv`
  - `pattern_hierarchy.csv`
  - `patterns/pattern_N.png`

### 4. Evaluation

Files: `evaluate.py`, `main.py`, `synthetic_gold_standard.csv`

- Added a dedicated synthetic gold standard file:
  `synthetic_gold_standard.csv`.
- Evaluation now reports both exact and contains precision/recall.
- Exact matching requires the mined pattern to equal the gold pattern.
- Contains matching also counts a mined super-pattern when it contains the gold
  behavior as a subpattern.
- `main.py` now writes `evaluation_metrics.json`.

This is important because SUBDUE often reports a larger structure that includes
the intended behavior plus one extra edge.

### 5. Visualization

File: `visualize_instance_graphs.py`

- Added a small utility to render selected BIG instance graphs from
  `instance_graphs.pkl`.
- Example:

```powershell
.venv\Scripts\python.exe visualize_instance_graphs.py --graphs-path output_resource_80_model_original\instance_graphs.pkl --trace-ids 0,1,2 --output-dir output_resource_80_model_original\instance_graph_views
```

## Main Results

### 80% frequent behavior, no SUBDUE activity filter

Output folder:

`output_resource_80_behavior_only`

Result:

The strongest patterns are still dominated by low-value prefixes, for example:

```text
start_User_1 -> A-Create-Application_User_1 -> A-Submitted_User_1
```

Interpretation:

The 80% frequent-variant filter improves runtime before Inductive Miner, but
does not by itself prevent SUBDUE from finding trivial start/submission
patterns.

### 80% frequent behavior, with low-value SUBDUE activity filter

Output folder:

`output_resource_80_model_original`

Filter removed before SUBDUE:

```text
start, end, A-Create-Application, A-Submitted
```

Top pattern:

```text
W-Handle-leads-schedule_User_1
-> W-Handle-leads-withdraw_User_1
-> W-Complete-application-schedule_User_1
```

Support:

```text
1296 / 2475 traces = 52.4%
```

Interpretation:

After removing low-value activities, SUBDUE finds more meaningful work-practice
patterns instead of simply rediscovering the technical start/application
prefix.

### Synthetic Validation

Output folder:

`output_synthetic_validation_fixed`

Command:

```powershell
.venv\Scripts\python.exe main.py data\synthetic_validation.xes --attribute org:group --output-dir output_synthetic_validation_fixed --variant-coverage 1.0 --exclude-activities= --num-best 10 --min-size 1 --max-size 4 --limit 100 --gold-standard synthetic_gold_standard.csv
```

Results:

```text
Exact precision:    0.38
Exact recall:       0.75
Contains precision: 1.00
Contains recall:    1.00
```

Interpretation:

Exact matching is strict. The contains score shows that all deliberately
encoded gold-standard behaviors are recovered inside the mined SUBDUE
structures.

### Synthetic Hierarchical SUBDUE

Output folder:

`output_synthetic_validation_hierarchy`

Command:

```powershell
.venv\Scripts\python.exe pattern_mining.py --graphs-path output_synthetic_validation_fixed\instance_graphs.pkl --output-dir output_synthetic_validation_hierarchy --num-best 10 --min-size 1 --max-size 4 --limit 100 --iterations 2 --exclude-activities=
```

Result:

The output contains both `core` and `hierarchical_expanded` rows in
`pattern_stats.csv`. This confirms that compressed SUBDUE hierarchy patterns
are expanded back into original event edges for interpretation.

## How to Read the Important Output Files

- `variant_filter_stats.json`: how many traces/variants were retained before
  Inductive Miner.
- `mining_filter_stats.json`: which low-value activities were removed before
  SUBDUE.
- `instance_graphs.g`: BIG-style textual instance graphs.
- `pattern_stats.csv`: main table for pattern size, support count, and support
  fraction.
- `trace_pattern_matrix.csv`: rows are traces, columns are patterns, value `1`
  means the pattern occurs in that trace.
- `pattern_hierarchy.csv`: whether each pattern is a core pattern or an
  expanded hierarchical pattern.
- `patterns/pattern_N.png`: visual pattern examples for the report.
- `evaluation_metrics.json`: precision/recall metrics for runs through
  `main.py`.

## Recommended Assignment Story

The most defensible result narrative is:

1. We preprocess the log by fusing activity with an organizational attribute.
2. We preserve `original_activity` so the process model remains tractable.
3. We retain the most frequent trace variants covering 80% of cases before
   Inductive Miner, following the teacher's suggestion.
4. BIG generates instance graphs from the process model and relabelled log.
5. SUBDUE mines frequent behavioral graph patterns.
6. Low-value activity filtering before SUBDUE is necessary because otherwise
   the top patterns are dominated by deterministic start/application-submission
   behavior.
7. Synthetic validation confirms that the pipeline can recover deliberately
   encoded organizational patterns.
8. The hierarchical SUBDUE layer is handled by expanding compressed patterns
   back to original events.
